Creator-first AI case learning platform

GoodCase.ai 项目介绍

一个 creator-first 的 AI 案例学习平台：先看真实 Case，再决定用哪个模型；登录后点赞可解锁完整 Prompt。

一句话介绍 仓库当前围绕“真实案例浏览 + 双榜单判断 + 登录点赞解锁 Prompt” 这条主链路，已经做出可操作的 MVP。
正式品牌：GoodCase.ai 正式域名：goodcase.ai 当前阶段：MVP 已可操作 定位：creator-first
当前状态

首页、案例库、详情页、登录页已可用；AI 喜爱榜与 AI 稳定榜第一版已完成。

认证状态

Supabase 客户端注册、登录、退出、会话监听已接通；/auth/callback 与基础 SSR Auth 已接通。

数据状态

点赞已接入 public.case_likes；候选池到审核再到发布的数据库与脚本流程已有雏形。

未完成部分

供给与审核后台仍待补齐，全站服务端用户态还没有系统性覆盖到所有页面与接口。

Core Features

核心功能

以下功能均可在当前仓库中找到直接对应的页面、组件、数据层或 Supabase 结构，不含推测性描述。

真实案例浏览与分类筛选

首页与 /cases 已可浏览案例；列表支持 全部 / AI 视频 / AI 编程(UI) / AI 图像 筛选。

AI 喜爱榜 + AI 稳定榜

首页基于案例数据生成两类 Top 10 榜单，分别帮助用户看“喜欢度”和“稳定性”。

登录后点赞，解锁完整 Prompt

未登录用户点击点赞会跳转登录；已登录用户点赞后，详情页 Prompt 面板会从预览态切换为完整显示。

案例详情承载媒体、Prompt 与模型建议

/cases/[slug] 同时展示媒体内容、点赞数、复刻数、稳定分、推荐模型与成本档位。

服务端首屏用户态 + 客户端实时同步

首页、案例列表、案例详情已读取服务端用户态初值，点赞后客户端会实时同步解锁与计数状态。

候选导入与发布链路已有雏形

仓库包含 import:candidates 与 publish:cases 脚本，对应候选池、审核状态与发布入库流程。

Audience

适用人群

仓库当前产品定位是 creator-first，因此更适合围绕“案例学习、模型选择、Prompt 复用”这几类场景使用。

内容创作者与 AI 实践者

适合先看真实输出结果，再回到 Prompt 与模型组合做复刻或二次创作。

需要做模型选型的人

适合通过喜爱榜、稳定榜和详情页推荐模型，快速判断“先用哪个模型开跑”。

需要沉淀案例库的小团队

当前仓库已经有案例数据表、点赞表、候选池与发布脚本，适合继续向内容中台演进。

Tech Stack

技术栈

以下以当前依赖与仓库文档为准，优先展示已经出现在代码或官方说明中的技术选型。

前端框架

Next.js 16.2.2 + React 19.2.4 + TypeScript，采用 App Router 目录结构。

样式体系

Tailwind CSS 4 + 全局 CSS 变量，当前站点视觉基调集中在暖色纸感与大标题排版。

认证与数据

@supabase/ssr + @supabase/supabase-js，承接 Auth、Postgres 数据读取与点赞状态写入。

数据库约束

supabase/schema.sql 中定义了 profiles、cases、case_candidates、 case_likes 以及对应 RLS 策略。

工程校验

使用 ESLint 9 与 eslint-config-next 进行基础代码校验。

文档中的推荐正式栈

README 中写明推荐部署为 Vercel，媒体存储建议使用 Cloudflare R2，长视频阶段建议接入 Cloudflare Stream。

Structure Highlights

项目结构亮点

当前仓库规模不大，但边界已经比较清晰，后续继续扩展供给后台和服务端接口时不会从零开始。

src/app 负责页面入口

已包含首页、案例列表、案例详情、登录页与 auth/callback 路由，产品主链路集中在这里。

src/components 负责交互组件

站点外壳、登录表单、点赞按钮、Prompt 面板、媒体展示与 Auth Provider 都被拆成独立组件。

src/lib/cases.ts 是数据装配层

统一处理案例读取、分类过滤、榜单生成、媒体路径兜底，以及 “数据库优先 / mock 数据兜底”的回退逻辑。

src/lib/supabase/* 分离浏览器端与服务端能力

浏览器 client、服务端 client 与服务端用户态读取拆开维护，认证边界更清楚。

src/proxy.ts + auth/callback 形成 SSR Auth 基础设施

一个负责会话刷新与 cookie 回写，一个负责邮箱确认后的 code exchange for session。

scripts/ 与 supabase/ 为内容流转预留了后手

导入候选、发布 approved 案例、表结构与 RLS 规则已经在仓库内，对后续审核后台接入比较友好。

How To Use

使用方式

下面的方式完全对应当前仓库已有脚本与文件，不要求额外依赖未知工具。

1. 本地启动项目

先安装依赖，再启动开发环境。

npm install
npm run dev
2. 配置环境变量

参考仓库中的 .env.example 与现有 Supabase 代码路径，至少需要配置公共 URL 与匿名 Key 才能跑通真实登录。

3. 按页面主链路体验

访问 / 看首页与双榜单，访问 /cases 看案例库，进入任意详情页后登录并点赞，可验证 Prompt 解锁逻辑。

4. 查看数据结构与策略

如果要继续开发内容流转或权限规则，优先读 supabase/schema.sql。

5. 执行内容导入与发布脚本

仓库已有两条脚本：一条导入候选案例，一条发布审核通过的案例；这两条脚本都需要 Supabase 服务端密钥环境变量。 

npm run import:candidates -- --file=tmp/case-candidates.json
npm run publish:cases -- --batch=<batch-id>

当前口径提醒： 这个项目已经不是纯 Demo，但也还不是正式规模化上线版本。最准确的阶段描述仍然是 MVP 已可操作，供给与审核后台待补齐。
